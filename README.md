# 病理切片名单划分与交付

FastAPI + SQLite 的病理研究切片名单工具：网页上传/追加 CSV，按全库精确划分训练集与盲测集，
并把训练名单交付给一个**独立**的接收服务，核实回执后区分「终态接纳 / 终态拒收 / 状态未明」。

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

* 网页应用：<http://localhost:8000>
* 接收服务 A（默认）：<http://localhost:8001>
* 接收服务 B（用于演练“换地址”）：<http://localhost:8002>

三个服务各有独立的数据卷（`app-data`、`receiver-a-data`、`receiver-b-data`）与各自的 SQLite 文件，
所以“已交付”是外部事实，而不是应用自己的一个标志位。

网页上的操作顺序：上传 CSV → 填测试集良性/恶性张数 → 求解并发布名单 →
下载测试/训练名单 → 交付训练名单 → 在交付表里「核实」或「重试」。
失败、超时或重启后都可以用页面上的「核实 / 重试」按钮继续，不会重复接纳。

### 演示“交付归属”（本次修复的行为）

1. 接收方地址保持默认 `http://receiver-a:8000`，交付一份训练名单。
   在 A 的页面把故障设为 `timeout`（服务端已写入、响应丢失），本地交付停在「待核实」。
2. 把网页上的接收方地址改成 `http://receiver-b:8000`，点「重试」或「核实」。
   **B 不会收到任何名单**：应用始终回到该交付登记时的原接收方 A 去接续/核实；
   A 恢复后核实会得到原回执，切片永久禁入测试。
3. 同址换卷：停掉 A、删除 `receiver-a-data` 卷再启动。地址没变，但数据卷身份变了，
   旧交付依然只认原卷，**不会**把名单重发给“地址相同、卷已更换”的替代方；
   旧交付保持「待核实」，切片继续禁入。恢复原卷后即可正常核实。
4. 原接收方正常重启（卷不变）不影响核实/重试；它的身份存在自己的数据卷里。


## CSV 格式

```csv
slide_id,patient_id,repeat_group,malignancy
S001,P001,G1,benign
S002,P002,G1,malignant
S003,P001,,benign
```

* 表头可省略（无表头时接受 3 列 `slide,patient,malignancy` 或 4 列）。
* `repeat_group` 可空；空表示“没有重复图组”，不会与任何切片相连。
* `malignancy` 只接受 `benign` / `malignant`（也识别 良/恶）。
* 总库最多 **100** 条。**整批校验**：任一行非法则整批不写入；重复切片号会被跳过而不是覆盖。

## 规则

**隔离**：切片按「同患者号」或「同一非空重复图组」传递连通。一个连通组必须整个进同一集合，
因此组内任意切片被禁入测试，整组都只能进训练。

**精确划分**：给定测试集良性 `b` 张、恶性 `m` 张，其余全部进训练集。
求解器对完整连通组做 0/1 精确子集和（动态规划，状态空间 ≤ 101×101），
不做贪心或随机抽样。无解时返回具体原因（配额超过全库 / 超过禁入后可用数 / 连通组组合
无法精确匹配，并给出最接近的可行组合）。

**交付与禁入**

| 交付状态 | 对测试集的影响 |
| --- | --- |
| 待核实（pending） / 查无记录 / 超时 / 非 2xx | 相关切片**及其当前连通组**暂禁入测试 |
| 终态接纳（accepted） | 相关切片**永久**禁入测试 |
| 终态拒收（rejected，已绑定原接收方） | 只解除**该笔**交付带来的禁入；切片重新变为“未明交付”，仍需显式交付才能进测试 |
| 旧库记录，无法证明原接收方 | **保留禁入**并说明原因；即使旧记录写着“拒收”也不解除（见下） |

禁入集合每次都从交付表重新推导，不做缓存，所以崩溃或重启不会丢失限制；
拒收也不会顺带清掉其它交付的限制。

**交付归属（原接收方）**

每笔交付在**发送前**就登记其原接收方：

* 发送前先读取接收服务的稳定身份 `receiver_id`（由接收服务在自己的数据卷里生成一次，
  正常重启不变；换卷则变），把它和当时使用的地址一起写入交付记录。
* 此后**只有该原接收方**能确认或接续这笔交付。改配置地址不会把旧交付转发给新地址；
  同地址换数据卷得到的是不同身份，同样被拒绝。
* 接收服务也会校验请求里携带的 `expected_receiver_id`，不是自己的交付直接 409，
  不会替别人写入；回执里带有 `receiver_id`，发送方核不上即视为“未明”。
* 核实/重试始终请求**登记时的地址**，所以“换成 B 再点重试”不会让 B 收到名单；
  原接收方离线只影响它自己的交付，其它交付和其它接收方照常工作。
* 原接收方正常重启（同一数据卷）身份不变，可以继续核实/重试。

**旧库迁移**

启动时会为旧库补上 `receiver_id`/`receiver_url`/`binding` 三列，既有行标记为
`legacy_unproven`：

* 旧记录若已是**终态接纳**：保持永久禁入，不降级；
* 旧记录为**未明**或**拒收**：无法证明是哪个接收方，按保守原则**继续禁入**并在页面上
  说明原因；系统不会拿当前配置的地址去“重试/核实”这些旧记录；
* 已有接纳记录永久保留。

**并发与迟到回执**

* 终态写入是条件更新（`WHERE status='pending'`），并发重试 / 迟到回执 / 启动核实
  只有**第一个**终态生效，后到的相反结果不会覆盖已记录的接纳，也不会解除限制；
* 发送前先落库，进程崩溃后重启仍能看到“待核实”并继续核实/重试。

**名单重判**：每次补传、交付状态变化（以及启动时）都会用当前库内容和当前交付状态重判所有旧名单。
未纳入名单的新切片若与某测试切片属于同一连通组，或名单内切片被禁入，该名单即
“隔离失效”，停止下载并显示原因；重新划分出合格名单后恢复可下载。
核实一旦得到终态（接纳或拒收）会立即重判所有旧名单：失效的立即停供。

**交付协议 / 崩溃安全**

1. 发送前先把「待核实」记录和这份训练名单的冻结副本写入数据库（同一事务）。
2. 发送前读取接收方身份并绑定；之后只向该原接收方发送/核实（见“交付归属”）。
3. 向接收服务 POST。接收服务按交付号写入一次终态，回执号固定；
   同一交付号重复提交只返回原回执，不会二次接纳；身份不符的请求直接 409。
4. 超时 / 连接中断 / 5xx / 404 一律记为“状态未明”，切片继续暂禁入测试；
   之后可「核实」（GET 交付号，核对校验和与接收方身份）或「重试」（用同一交付号重发）。
5. 每次启动会重判所有名单并重新核实所有待核实交付，不会自动解除任何限制；
   待核实交付按各自绑定的原接收方核实，与当前配置地址无关。
6. 求解在写事务之外进行；发布时在事务内比对库指纹与交付代次，期间有任何补传/交付变化
   则丢弃结果、不发布（“过期计算不得发布”）。名单与完整成员表在**同一事务**写入，
   写入失败不会留下半份名单。

## API（便于自查/脚本）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/library` | 总库与容量 |
| GET | `/api/restrictions` | accepted / uncertain / unproven / barred 及原因 |
| GET | `/api/plans` | 名单（含状态、原因、交付） |
| GET | `/plans/{id}/download/{test\|train}` | 下载 CSV；失效时 409 + 原因 |
| POST | `/plans` | 表单 `benign_count`,`malignant_count` |
| POST | `/plans/{id}/deliver` | 登记待核实并发送 |
| POST | `/deliveries/{id}/verify` / `retry` | 核实 / 重试（只访问原接收方） |
| GET | `/api/deliveries` | 交付列表（含 `receiver_id`/`binding`） |

接收服务：`GET /api/identity`、`POST /api/deliveries`（可带 `expected_receiver_id`）、
`GET /api/deliveries/{id}`、`GET /api/deliveries`，
以及模拟控制 `POST /api/simulate`（`fault` ∈ `none|http500|http404|http_verify500|timeout|slow|drop_after_store`，
`refuse=1` 模拟拒收）。终端终态不可修改（`POST /api/deliveries/{id}/reject` 返回 409）。

## 本地开发与测试

```bash
python3 -m pip install -r requirements.txt
python3 -m pytest tests -q

# 两个进程本地跑
RECEIVER_DB_PATH=/tmp/r.sqlite3 uvicorn receiver.main:app --port 8001 &
APP_DB_PATH=/tmp/a.sqlite3 RECEIVER_URL=http://127.0.0.1:8001 uvicorn app.main:app --port 8000
```

`examples/library.csv` 可直接用于网页上传。

另有真实 HTTP 端到端自测（会自行拉起两个接收进程和应用进程，复现“换地址/换卷”场景）：

```bash
python3 scripts/e2e_smoke.py
```
